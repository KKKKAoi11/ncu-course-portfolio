## 三、每周提交作业的标准流程

```bash
git pull origin main              # 1. 先把云端最新版本拉下来
git add labs/week03               # 2. 把本周改动放进"待提交区"
git commit -m "docs(week03): 完成 XX 实验报告与代码"   # 3. 打包成一个存档点
git push origin main              # 4. 上传到 GitHub
```

### 提交信息推荐格式

`<类型>(<范围>): <简述>`，例如：

| 类型 | 含义 |
| :--- | :--- |
| `feat` | 新增功能 / 新实验 |
| `fix` | 修复错误 |
| `docs` | 仅修改文档 / 报告 |
| `refactor` | 重构代码（功能不变） |
| `chore` | 杂项（如调整 .gitignore） |

## 四、写给新人的白话术语表

| 术语 | 大白话解释 |
| :--- | :--- |
| **仓库（Repository）** | 可以理解成一个"**带时光机的云盘文件夹**"。普通文件夹改了就改了；仓库会把你每次改动都存成一个"存档点"，随时能回到过去的任意时刻。 |
| **Commit（提交）** | 游戏里的"**存档**"。打完一小关就存一次，写清楚这次存了什么；后面打崩了可以读档重来。 |
| **.gitignore** | 一张"**免打扰名单**"。像 `.log` 日志、`node_modules` 依赖包这类又大又没必要的文件，写进名单后 Git 就当它们不存在，不会上传。 |
| **Push（推送）** | 把本地的存档**上传同步到云端**（GitHub），相当于云盘的"同步"按钮。 |
| **Pull（拉取）** | 反过来，把云端的最新内容**下载到本地**。多人协作或换电脑前必做。 |
| **远端（Remote / origin）** | 云端那个仓库的地址。"推送到远端"就是上传到 GitHub。 |
| **暂存区（Staging Area）** | 快递打包台。挑出要寄的东西放上台面（`git add`），然后统一封箱发货（`git commit`）。 |

## 五、使用约定

1. 一个大文件（> 50 MB）不要直接放进仓库，改用链接或 Git LFS。
2. 绝不提交密码、密钥、身份证号等隐私内容（`.gitignore` 已屏蔽常见密钥文件）。
3. 每周实验完成后立即提交一次，避免学期末一次性堆积。
4. 提交前自查：`git status` 看一下，确认没有把不该传的文件加进来。
